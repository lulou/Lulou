PART 1 — FIX CHAT SWIPE-BACK WHITE SCREEN

ROOT PROBLEM

The chat is being translated to the right, but the Connections screen is not actually rendered underneath it. The page background is therefore exposed as white.

Required architecture:

1. While an inline chat is open, keep the Connections page mounted underneath the chat.

Structure:

<div className="connections-layer">
 existing Connections screen
</div>

<div ref={chatShellRef} className="chat-layer">
 existing _MatchChat screen
</div>

Required styles:

Connections layer:
- position: absolute
- inset: 0
- z-index: 0
- background must match the real Connections page
- remain mounted while chat is open
- pointer-events: none while the chat covers it

Chat layer:
- position: absolute or fixed inside the existing app viewport
- inset: 0
- z-index: 1
- background must be opaque
- will receive translate3d during swipe

Do not reveal document.body, a blank wrapper or a fake white background.

2. During swipe:

- translate only the chat layer
- Connections remains stationary underneath
- optionally start Connections at translateX(-20px) and interpolate toward 0 for depth
- add a subtle shadow to the moving chat’s left edge
- do not navigate or unmount during touchmove

3. On successful swipe:

- animate the chat layer from its current position to 100vw
- wait for transitionend
- only then call handleLeaveChat()
- reset transforms after the chat has closed

4. On cancelled swipe:

- animate chat back to translate3d(0,0,0)
- clear active gesture refs only after snap-back finishes

PART 2 — MAKE SWIPE WORK ON THE FIRST ATTEMPT

Inspect the current swipe lifecycle.

Fix all of these possible stale-state problems:

- active ref not reset after touchcancel
- dx value left from previous gesture
- RAF still pending
- transition still applied at the next touchstart
- first touch rejected because a stale modal/profile ref is true
- touchend reading a stale React state value instead of the latest ref
- handle element losing listeners after rerender
- swipe handle covered by the visible back button/header

Required touch lifecycle:

touchstart:
- cancel any pending RAF
- remove transition immediately
- reset current dx to 0
- reset direction lock
- reset cancelled flag
- store start coordinates/time
- set active true

touchmove:
- use latest values from refs only
- once horizontal direction wins, keep it locked
- update current dx ref on every move
- render transform from that exact ref

touchend:
- use current dx ref, not React state
- decide leave/snap exactly once
- set active false only after the decision is captured

touchcancel:
- snap back
- completely reset all refs

The first valid swipe from the edge must visibly move the chat.

Keep the activation strip wide enough for real use:
- 44px from the left edge
- do not place it underneath another element
- z-index above chat content
- below blocking modals
- touch-action: none

PART 3 — FIX PROFILE SHEET JUMPING OUT

ROOT PROBLEM

The profile is being hidden/unmounted or its close callback is firing before the sheet visibly follows the drag and completes its animation.

Required architecture:

There must be two distinct elements:

Backdrop:
- fixed/absolute
- covers chat
- fades independently

Sheet:
- sheetContainerRef attached to the actual large rounded profile panel
- the transform must be applied to this exact element
- not to the tiny grab-handle wrapper
- not to the profile content image
- not to a parent that is conditionally removed during dragging

1. During touchstart:

- do not call setShowProfilePanel(false)
- do not call the profile toggle callback
- do not alter conditional rendering
- set drag active
- remove transition from the actual sheet
- preserve current open state

2. During touchmove:

Apply directly to sheetContainerRef:

transform: translate3d(0, ${dy}px, 0)

The actual entire sheet must follow the finger continuously.

Apply backdrop opacity separately.

Do not:
- use React state per pixel
- change sheet height
- change top/bottom values
- set display:none
- toggle showProfilePanel
- trigger an onClick close
- let the drag touch bubble into a backdrop click handler

Call:
- preventDefault()
- stopPropagation()

on the drag-zone touch events.

3. On touchend below threshold:

- animate the same sheet back to translate3d(0,0,0)
- backdrop returns to full opacity
- keep showProfilePanel true

4. On touchend above threshold:

- animate the sheet from its current translateY to 100%
- fade backdrop
- wait for transitionend on sheetContainerRef
- only after transition completion call setShowProfilePanel(false)

Use a guarded 300ms fallback only if transitionend does not fire.

5. Prevent accidental backdrop closure:

Backdrop close must only run when:

event.target === event.currentTarget

Dragging the handle must never trigger the backdrop click/touch close callback.

6. Do not use velocity alone to close from a tiny movement.

Profile close rule:

- distance >= 25% of actual sheet height
OR
- distance >= 80px AND velocity >= 0.75 px/ms

A short touch/flick must not make the profile instantly disappear.
