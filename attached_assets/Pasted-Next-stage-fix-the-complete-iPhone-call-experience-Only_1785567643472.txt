PART 1 — SLIDE TO ANSWER

Replace the current green Answer button with a horizontal slide-to-answer control.

Required UI:
- caller photo
- caller name
- “Lulou audio call” or “Lulou video call”
- ringing status
- horizontal slider near the bottom
- draggable circular green phone icon
- text: “slide to answer”
- separate red Decline button

Required behaviour:

1. The green phone icon must visibly follow the user’s finger from left to right.

2. Fill or highlight the slider track progressively as the icon moves.

3. Accept the call only when the phone icon reaches at least 80% of the available track distance.

4. When released below the threshold:
- smoothly return the icon to the starting position
- keep the call ringing

5. When the threshold is reached:
- lock the slider to prevent duplicate acceptance
- stop the ringtone immediately
- call the existing answer-call function exactly once
- enter the active call screen

6. Use native touch handling that works on iPhone:
- dedicated drag element
- touch-action: none
- touchstart/touchmove with passive:false where required
- requestAnimationFrame
- transform: translate3d(...)
- do not cause React rerenders for every pixel

7. Decline must:
- stop the ringtone
- call the existing decline function
- reset incoming-call state
- not consume call quota for declined or failed calls

8. Keep an accessible non-drag Answer action for assistive technology, but do not allow an ordinary short tap to accidentally accept the call.

PART 2 — FIX MUTE

The mute button must control the real current local microphone MediaStreamTrack.

On mute:

localStream.getAudioTracks().forEach(track => {
 track.enabled = false;
});

On unmute:

localStream.getAudioTracks().forEach(track => {
 track.enabled = true;
});

Requirements:
- use the current live local stream, not a stale stream captured earlier
- remote user must stop hearing the local user
- incoming remote audio must continue
- icon changes immediately
- label changes between Mute and Unmute
- muted state is visually obvious
- do not renegotiate or restart the call
- reset to unmuted when a new call begins
- safely handle missing or ended microphone tracks

Development-only logging:
- [CALL_MUTE] requested
- current track count
- track.enabled
- track.readyState
- track.muted
- [CALL_MUTE] applied

Do not expose diagnostic logs in the production UI.
