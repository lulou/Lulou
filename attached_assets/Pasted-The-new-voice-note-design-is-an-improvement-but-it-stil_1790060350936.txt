The new voice-note design is an improvement, but it still needs another refinement pass.

Functionality is working, so DO NOT break the working voice-note send / receive / playback pipeline.

The remaining problems are:

1. The mic icon is still temperamental and does not reliably respond every single time.
2. The recording interaction should feel more tactile and premium.
3. When the user holds the mic icon to record, I want the mic icon to expand slightly while the press is active.
4. The overall voice-note interaction can still feel more polished and iOS-native.
5. Voice-note messages are NOT contributing correctly to unread/message counts.
6. Voice-note messages are NOT triggering the same Lulou notification behavior as normal text messages.
7. If the recipient is not in the exact chat, a newly received voice note should behave like a normal unread message:
  - Connections badge increments
  - relevant conversation unread count increments
  - push notification is sent if push notifications are enabled
8. If the recipient is already inside the exact open chat and the app is visible, do NOT create a redundant unread count or foreground push notification.

==================================================
1. MIC INTERACTION MUST BE 100% RELIABLE
==================================================

The mic button must respond correctly every time.

Audit the exact live production interaction handling.

Check for:

- pointerdown not firing
- pointerup missed
- pointercancel mishandled
- touch/mouse duplication
- passive touch listeners
- event propagation conflicts
- drag threshold conflicts
- composer rerender interrupting the gesture
- stale refs
- permission request race
- multiple MediaRecorder attempts
- state transition races
- long-press firing twice
- touch release outside button not stopping correctly

Do not just increase the hit area and call it fixed.

Find the real cause of the temperamental behavior.

==================================================
2. USE ONE AUTHORITATIVE PRESS GESTURE
==================================================

Use Pointer Events as the primary interaction:

pointerdown
pointermove if needed
pointerup
pointercancel

Use pointer capture so the gesture stays owned by the mic button even if the finger moves slightly.

On pointerdown:

- capture pointer
- begin press visual state immediately
- begin recording according to existing logic

On pointerup:

- release pointer capture
- finalize recording once

On pointercancel:

- cancel/cleanup safely

Do not let touch + pointer handlers trigger the same recording twice.

Only use a fallback for older iOS where genuinely necessary.

==================================================
3. EXPAND MIC ICON WHILE HOLDING
==================================================

When the user presses and holds the mic:

the mic control should subtly expand.

Desired behavior:

idle:
normal mic size

press/hold:
scale to approximately 1.08–1.12

release:
smoothly return to 1.0

Use a short premium transition such as:

120–180ms
ease-out on press
slightly softer return

Do NOT make it bounce dramatically.
Do NOT make it huge.
Do NOT use a game-like pulse.

It should feel like iOS touch feedback.

==================================================
4. ADD SUBTLE PRESSED-SURFACE FEEDBACK
==================================================

While recording is actively being held:

- mic icon slightly enlarges
- surrounding touch surface may gain a subtle Lulou wine/blush tint
- optional very soft halo/ring around the mic

Keep it elegant.

No neon.
No Android green.
No giant glow.

==================================================
5. RECORDING START FEEDBACK MUST BE IMMEDIATE
==================================================

The user should know instantly that the hold registered.

On pointerdown:

within the same frame:
- mic visually expands
- active recording state begins visually
- timer/waveform starts as soon as MediaRecorder actually starts

Do not leave a dead-feeling delay while waiting on async permission if permission has already been granted.

If permission is being requested for the first time:
show a clear temporary pending state.

==================================================
6. MINIMUM PRESS / ACCIDENTAL TAP HANDLING
==================================================

Prevent accidental 50ms taps from creating broken micro-recordings.

Use a sensible minimum-recording rule.

For example:

- if user releases almost instantly, cancel rather than send
- once threshold is reached, treat as valid recording

Do not make the threshold feel sluggish.

==================================================
7. DO NOT REQUIRE PERFECT FINGER POSITION
==================================================

Once recording has started:

the user should not need to keep their finger pixel-perfectly centered over the mic.

Pointer capture should allow slight movement without losing the gesture.

This is especially important on iPhone.

==================================================
8. RELEASE MUST ALWAYS FINALIZE CLEANLY
==================================================

The most important reliability behavior:

user presses
→ recording starts

user releases
→ recording stops/finalizes exactly once

No sticky mic.
No recording continuing.
No double-send.
No failed state caused by two stop calls.

Guard finalization with single-flight logic.

Do not accidentally cancel because the finger moved a few pixels.

Use a meaningful threshold if drag-to-cancel exists.

keep the explicit cancel control.

==================================================

A voice note is a real chat message and must participate in unread/message counts exactly like a normal text message.

Current bug:
voice-note messages are arriving, but the recipient is not getting the expected unread/message count.

Fix this.

Expected behavior:

If User A sends one voice note to User B while User B is NOT inside that exact open chat:

→ User B conversation unread count +1
→ Connections bottom-nav badge +1
→ Active Chats unread indicator/count updates immediately

Counts are by unread MESSAGE, not merely unread conversation.

Example:

Aggregate across multiple chats.
