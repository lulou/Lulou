- have no working handler

- call progression

- settings
- authentication rules

FIX THE CONNECTIONS TRY AGAIN BUTTON

When pressed it must:

1. Show a visible loading state:
  - button text changes to “Trying again…”
  - button disables only while the request is active

2. Retry the actual failed Connections requests:
  - selected account/session verification if required
  - matches/connections list
  - unread counts
  - any required profile/session bootstrap dependency

3. Use the exact React Query keys used by the Connections page.

4. Clear only the relevant error state.

5. On success:
  - render the Connections page immediately

6. On failure:
  - keep the error screen visible
  - re-enable the button
  - show the real error message or status
  - do not silently do nothing

Do not use only:

window.location.reload()

as the primary fix.

A reload fallback may exist only after the proper retry fails.

FIX SESSION RETRY

The Session verification Retry button must:

- re-run the actual server session verification request
- refresh the Supabase access token first if necessary
- use the current authenticated session
- enter the app on success
- show the real failure on error
- never remain stuck in a loading state

FIX SIGN OUT ON ERROR SCREENS

Sign out must work even when Railway is unavailable.

It must:

- call Supabase signOut
- clear local auth/session state
- clear React Query cache
- clear active-session state
- navigate to the login screen

It must not depend on a successful Railway request.
