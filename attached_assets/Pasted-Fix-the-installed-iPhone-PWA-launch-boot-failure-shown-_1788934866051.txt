Fix the installed iPhone PWA launch/boot failure shown in the attached REAL screenshot.

Current symptom:

I tap the installed Lulou app icon on iPhone.

The app opens to a completely blank white screen.

Nothing appears after waiting.

No login.
No reconnect screen.
No app shell.
No error message.
No navigation.
No recovery.

This is a production boot failure.

Do NOT treat this as a cosmetic issue.

## PRIMARY GOAL

Opening the installed Lulou PWA must always resolve into one of these valid states:

1. authenticated app
2. login screen
3. onboarding flow
4. genuine recoverable error screen

It must NEVER remain on a permanent blank white screen.

## 1. FIND THE EXACT BOOT FAILURE

Trace the full installed-PWA startup path.

Inspect:

- `index.html`
- service worker
- root React mount
- `App.tsx`
- auth initialization
- session restoration
- onboarding resolver
- router initialization
- lazy imports
- API bootstrap
- error boundaries
- suspense/loading states

Determine the FIRST point where rendering stops.

Do not just add a spinner over the blank screen.

Find the actual failure.

## 2. CAPTURE RUNTIME ERRORS

Inspect production Safari/PWA console/runtime errors if available.

Look for:

- uncaught JS exceptions
- failed dynamic imports
- stale asset hashes
- chunk-load errors
- hydration/root-mount failure
- undefined config/env values
- auth initialization rejection
- service-worker fetch errors
- bad cached HTML referencing deleted JS bundles
- unhandled promise rejection
- router crash
- infinite pending state

Report the exact error category.

## 3. SERVICE WORKER / STALE BUNDLE AUDIT

This looks highly consistent with an installed PWA opening stale cached HTML or stale JS after deployment.

Audit the service worker carefully.

Check whether:

- old `index.html` is cached
- old asset filenames are cached
- current `index.html` references new asset hashes
- service worker returns stale HTML
- deleted Vercel assets are still requested
- chunk requests return 404
- service worker update activates but old client never refreshes
- PWA remains controlled by an obsolete worker

Static asset caching must never leave the installed app pointing at deleted bundles.

## 4. DO NOT CACHE THE APP SHELL UNSAFELY

If current SW uses cache-first for navigation requests, fix it.

For navigation/app-shell requests, use a safe strategy such as:

- network-first with fallback to last known good shell

or another robust versioned strategy.

Do not indefinitely serve an obsolete `index.html`.

Auth/API routes must remain network-authoritative.

## 5. CHUNK LOAD RECOVERY

If the app hits a stale dynamic-import/chunk error after a deployment:

recover once automatically.

For example:

- detect chunk-load failure
- unregister/update stale worker if appropriate
- clear only obsolete app-shell/static caches
- reload once

Guard with a one-time session flag so it cannot create an infinite reload loop.

Do NOT wipe:
- auth unnecessarily
- user data
- unrelated local preferences

## 6. ROOT RENDER FALLBACK

The React root must never leave users with an empty document.

Add/verify a top-level error boundary / bootstrap fallback.

If boot throws before authenticated state resolves, show a minimal Lulou recovery UI rather than white.

Example:

“Lulou couldn’t finish loading.”

with:

“Try Again”

But only as a fallback.

The real goal is to make normal boot succeed.

## 7. BOOT TIMEOUT SAFETY

If auth/app bootstrap is waiting forever because a promise never resolves:

add a bounded timeout.

States should be explicit:

- booting
- authenticated
- unauthenticated
- onboarding
- recoverable_error

Do not allow:

`loading=true`

forever.

If boot exceeds a sensible threshold:

- attempt one controlled recovery
- then show recovery UI

## 8. AUTH INITIALIZATION MUST NOT BLOCK FOREVER

Audit:

- `getSession()`
- token refresh
- auth listener setup
- app session establishment
- `X-Session-Id`
- profile/settings load

Every awaited step needs:

- success
- failure
- timeout/recovery

No unresolved promise should leave the root blank.

## 9. INITIAL HTML MUST RENDER SOMETHING

Before React fully boots, ensure the app has a basic root/loading surface.

Even if JS fails, the user should not stare at pure white indefinitely.

Use a lightweight Lulou boot shell if appropriate.

Do not create a visually heavy splash redesign.
