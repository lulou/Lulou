Top 10 User-Facing Bugs (Priority Order)
TURN server not configured — Every browser console logs "TURN not configured — calls may fail on restricted networks." Users behind NAT, firewalls, or on mobile networks will have WebRTC peer connections fail silently. Calls appear to connect but audio/video never flows. This affects every call in the app.
Local Drizzle tables may not exist in production — call_credits, saved_wheel_profiles, user_benefits, user_elevates are in local PostgreSQL. If drizzle-kit push was never run in the production environment, every feature depending on these tables either silently fails or throws 500 errors. This includes: phone credit gating, call bundles working, undo-pass, Elevate boosts, Save For Later.
Users start with 0 phone credits — The "Start Call" button is disabled by default for all users with no credits. There is no free trial credit granted on signup. New users who reach the call stage will see a disabled grey button with "You need phone credits" — with no way to get a free credit and no clear path shown beyond buying from Extras. The UX has a hard wall.
custom_signals column guard — _hasCustomSignalsColumn defaults to false. If the Supabase profiles table does not have a custom_signalscolumn, every user's custom personality signals are silently dropped on save. There is no error, no indication to the user that the data was not saved.
Undo Pass always visible but always fails without credits — The ↩️ button renders on /discover for all users. Tapping it with 0 undo-close credits shows a destructive toast "No undo credits." Users have no way to get this credit without purchasing. The button being always visible but always failing is misleading.
Discovery pool empty for most users — Until real users sign up with matching gender/preference combinations, /discovershows "All caught up" for everyone. There is no seed data or test-user fallback.
Non-English languages incomplete — The language system falls back to English for any missing key. Most non-English languages have only partial translations. A user who selects French, German, etc., sees a mixed English/target-language UI with no indication that translation is partial.
Call credit consumption only works if initiator completes first— consumeCallCredit is only called when result.counted === true. If the callee calls /call/complete before the caller (e.g., they hang up first), the caller gets counted: false and no credit is consumed even for a 30-minute call. Credit deduction is non-deterministic based on who hangs up first.
Intention Wheel Save For Later: no visual confirmation after save — After tapping the Star button in the post-spin overlay, if the saved_wheel_profiles insert succeeds, there is no UI change (the button doesn't become "saved", no badge, no confirmation). If it fails (table missing), the user sees nothing. The feature gives no feedback in either direction.
Incoming call rering stale guard complexity — The stale call protection uses armCallSession, endedMatchIdsRef, 90-second age checks, and armedTick/endedTick deps in a useMemo. This guards against phantom rings but the logic is complex enough that edge cases (tab switching, background/foreground, rapid consecutive calls) may still produce phantom ring overlays that cannot be dismissed.
