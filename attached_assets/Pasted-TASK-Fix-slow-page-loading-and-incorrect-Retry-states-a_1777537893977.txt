TASK:
Fix slow page loading and incorrect Retry states across the Lulou app.

CONTEXT:
The app is slightly faster, but still not close to App Store quality. Discovery, Connections, Profile, Messages, and other pages still feel too slow. Also, some pages show “Retry” too often, even during normal loading. Retry should only appear after an actual failed request, not every time the page is fetching or buffering.

PROBLEM:
The app likely mixes up loading, empty, and error states. It may be showing Retry during normal loading instead of showing skeleton loaders or cached content. Pages may also be blocking render while waiting for Supabase data.

GOAL:
Make every page feel instant:

* Page shell appears immediately
* Cached content appears immediately if available
* Skeleton loaders appear during normal loading
* Retry appears ONLY after a real error/failure
* No blank pages
* No unnecessary blocking spinners
* No repeated Supabase fetches unless needed

PRIORITY PAGES:

1. Discovery
2. Connections
3. Likes
4. Messages
5. Profile
6. Edit Profile

SOLUTION REQUIREMENTS:

1. Audit loading/error state logic

* Inspect all major pages for loading, error, empty, and retry states
* Identify where Retry is shown during normal loading
* Separate these states clearly:

  * loading = first fetch in progress
  * refreshing = background update while cached data is visible
  * error = request actually failed
  * empty = request succeeded but no data exists

2. Fix Retry behaviour

* Retry button must only show when error is not null
* Retry must not show during initial loading
* Retry must not show during route transitions
* Retry must not show while data is simply being fetched
* Retry must not show if cached data exists and a background refresh is happening

3. Add instant page rendering

* Render page layout immediately
* Show skeleton cards/lists during first load
* Show cached data immediately if already loaded
* Use small inline refresh indicators instead of blocking the whole page
* Keep previous data visible while refreshing

4. Improve Supabase fetch strategy

* Avoid duplicate calls on every route change
* Avoid refetching current user/profile repeatedly
* Avoid sequential fetches inside loops
* Fetch only required columns for each page
* Cache page data in state/context/session memory where safe
* Only refetch when stale, manually refreshed, or after user action

5. Discovery optimisation

* Initial render should show shell instantly
* Fetch limited first batch only
* Use optimized photo URLs
* Lazy-load non-visible images
* Keep previous discovery results when navigating away and back
* Do not fetch full profiles until needed

6. Connections optimisation

* Fetch only essential connection card data:

  * match id
  * other user id
  * display name
  * primary photo
  * last message preview if needed
  * last activity timestamp
* Do not fetch every profile field
* Do not fetch each connected user one by one inside a loop
* Cache results after first successful load

7. Likes optimisation

* Compare Likes with Discovery and Connections
* Identify why Likes feels faster
* Apply the same fast-loading pattern where appropriate

8. State model to use everywhere
   Use this pattern:

const [data, setData] = useState(cachedData || []);
const [isLoading, setIsLoading] = useState(!cachedData);
const [isRefreshing, setIsRefreshing] = useState(false);
const [error, setError] = useState(null);

Rules:

* isLoading = only true when there is no cached data and first fetch is happening
* isRefreshing = true when cached data exists and fresh data is being fetched
* error = only set when Supabase request fails
* empty state = only show when request succeeded and data.length === 0
* retry = only show when error exists
