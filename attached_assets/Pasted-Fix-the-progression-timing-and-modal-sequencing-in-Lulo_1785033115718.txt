Fix the progression timing and modal sequencing in Lulou.

CURRENT PRODUCTION BUG

The “Voice notes unlocked” popup is appearing late.

The attached screenshot shows:

- the conversation has already reached the first-call stage
- the call controls are already visible in the background
- both users were able to progress to the call stage
- only after that did the “Voice notes unlocked” modal appear

This is incorrect.

Voice notes must unlock at 8 completed messages each way, and the milestone must be handled before either user can proceed towards the 15-message call stage.

CORRECT PROGRESSION

Messages 1–7 each way:
- text only
- voice notes locked
- call locked

At exactly 8 completed messages each way:
- stop normal chat progression temporarily
- unlock voice notes
- show a premium celebratory milestone screen/modal immediately
- call must remain locked
- the user must acknowledge the milestone before continuing

Messages 9–14 each way:
- text and voice notes available
- call remains locked

At exactly 15 completed messages each way:
- stop normal chat progression temporarily
- show a separate premium “First call unlocked” celebration
- only after acknowledgement should the first-call stage and call controls become available

The voice-note modal must never appear after call controls are already visible.

SEQUENCE MUST BE SERVER-AUTHORITATIVE

Do not rely only on a delayed client useEffect.

The server response that processes the message reaching the threshold must return a progression event, for example:

{
 messageSaved: true,
 progressionEvent: {
   type: "voice_notes_unlocked",
   threshold: 8
 }
}

At 15 each way:

{
 messageSaved: true,
 progressionEvent: {
   type: "first_call_unlocked",
   threshold: 15
 }
}

The client must process that event immediately after the successful message response.

Do not wait for a later entitlement refetch, page refresh, polling cycle or component remount.

BLOCK THE NEXT STAGE UNTIL ACKNOWLEDGED

Add explicit milestone acknowledgement state.

For example:

- voice_notes_unlocked_at
- voice_notes_acknowledged_at
- first_call_unlocked_at
- first_call_acknowledged_at

Rules:

- reaching 8 unlocks voice notes but does not unlock the call
- reaching 15 marks the first call as eligible
- call controls must not render until first_call_acknowledged_at exists
- the chat must not render the call-stage interface underneath the voice-note milestone
- progression events must be acknowledged separately for each user
- one user acknowledging must not automatically dismiss the other user’s milestone

If the user reaches 15 while the voice-note milestone is still unacknowledged:

1. Show the voice-note milestone first.
2. After it is acknowledged, return the user to chat.
3. Do not immediately stack another modal over it.
4. Show the first-call milestone separately.
5. Only after that acknowledgement display the call controls.

PREVENT LATE POPUPS

When opening an existing conversation:

- if callStage > 0 and the voice-note milestone was never recorded, silently backfill it as acknowledged
- do not show a late voice-note popup over an existing call-stage conversation
- do not replay historical milestone celebrations for progressed conversations
- only show celebrations at the moment the user genuinely reaches that milestone

The screenshot scenario must never happen again.
