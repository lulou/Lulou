BUG 2 — STALE INCOMING RING PLAYS AFTER SIGN-IN

Immediately after signing in, an incoming call ringtone starts again even though no new live call was initiated.

This means stale call state, old realtime events or persisted ringing state are being restored after authentication.

Investigate:

- incoming call state in React
- realtime subscriptions
- call invitation rows in the database
- WebRTC signalling records
- localStorage/sessionStorage call keys
- cached React Query call data
- service-worker or push-notification call events
- duplicate Supabase realtime subscriptions after login
- call records left in ringing/connecting status
- previous call IDs restored on session hydration

Required behaviour:

- signing in must start with no ringing state
- only a genuinely new active incoming call invitation may trigger the ringtone
- old, ended, declined, expired or answered calls must never ring again
- reconnecting realtime must not replay historical INSERT events as new calls
- duplicate subscriptions must not produce duplicate ringing
- switching accounts must clear all previous account call state
- signing out must stop audio immediately and remove all call subscriptions
- refreshing the page must not restart an expired ringtone

SERVER-SIDE CALL EXPIRY

Incoming call invitations must have:

- created_at
- expires_at
- status

Allowed active statuses should be narrowly defined, for example:

- ringing
- accepted
- declined
- ended
- expired

On login or subscription startup:

- fetch only calls for the authenticated user
- require status = ringing
- require expires_at > now()
- ignore calls created before the current session unless still genuinely active
- automatically mark expired ringing calls as expired
- never ring from ended, declined, accepted or expired records

CLIENT-SIDE CLEANUP

On sign-out, account switch or component unmount:

- stop and reset the ringtone audio
- clear incomingCall state
- clear activeCallId
- clear pending call modals
- unsubscribe from every call channel
- remove any call-related timers
- invalidate/remove call-related query cache
- remove stale call keys from localStorage/sessionStorage

Prevent more than one call subscription per authenticated user.

Add diagnostic logging for:

- user ID
- call ID
- event type
- call status
- created_at
- expires_at
- whether the event was ignored or triggered ringing
- reason for ignoring stale calls
