LULOU — FULL APP PREMIUM iOS UI/UX AUDIT

OBJECTIVE

Audit the ENTIRE Lulou app and eliminate anything that visually or behaviorally feels Android, Material Design, generic web-app, or cheap/cross-platform.

The finished app must feel intentionally designed for premium iPhone/iOS use.

Think:

- premium native iOS dating app
- elegant
- restrained
- smooth
- tactile
- sophisticated
- consistent
- unmistakably Lulou

This is NOT a redesign of Lulou.

Preserve Lulou’s existing:
- brand identity
- colour palette
- typography direction
- logo
- functionality
- page structure
- dating flow
- Connection DNA
- Intention Wheel
- Discover
- Likes
- Connections
- Profile
- calls
- messaging
- monetisation

The goal is to remove Android/web-app visual language and replace it with polished iOS interaction/design language WITHOUT breaking functionality.

==================================================
RULE #1 — DO NOT BREAK THE APP
==================================================

This is primarily a presentation and interaction-polish task.

DO NOT rewrite working business logic just to improve appearance.

DO NOT change:
- API contracts
- database schema
- authentication
- matching logic
- candidate eligibility
- gender/preference logic
- distance filtering
- message quotas
- call progression
- Halo logic
- Open ❤️ persistence
- payments
- Connection DNA scoring
- Intention Wheel eligibility
- onboarding requirements
- existing user data
- routing unless required for an iOS navigation fix

Do not remove working functionality.

Do not introduce a second implementation of existing functionality.

Reuse existing components and logic wherever possible.

Before changing a shared component, determine every screen that uses it.

==================================================
TARGET: PREMIUM iOS FEEL
==================================================

Use modern iOS interaction principles while retaining Lulou’s unique visual identity.

The app should feel designed specifically for iPhone rather than copied from Apple or Android.

Use:

- generous spacing
- strong visual hierarchy
- subtle depth
- restrained shadows
- soft surfaces
- carefully controlled borders
- consistent premium corner radii
- clean typography
- deliberate whitespace
- smooth spring-like motion where appropriate
- subtle opacity/scale transitions
- high-quality pressed states
- proper disabled states
- clear hierarchy between primary and secondary actions
- large comfortable touch targets
- polished sheets and overlays
- safe-area-aware layouts
- natural iOS scrolling
- premium loading states
- subtle haptics only where already supported safely

Avoid excessive blur/glass effects.

Use them only where they genuinely improve hierarchy.

Lulou should remain warm, romantic and premium — not become a generic Apple Settings clone.

==================================================
NAVIGATION + SCROLLING
==================================================

Audit every screen for iPhone-native-feeling navigation.

Headers should behave intentionally.

Where a page is designed to scroll as one continuous surface, the header should participate naturally unless there is a deliberate reason for it to remain fixed.

Never allow content to accidentally move underneath an opaque fixed header.

Keep bottom navigation behavior consistent across the main app.

Respect:

env(safe-area-inset-top)
env(safe-area-inset-bottom)

Check installed iPhone/PWA mode as well as Safari.

Avoid nested vertical scroll containers unless absolutely required.

There should normally be ONE obvious vertical scroll owner per screen.

Scrolling must feel smooth and natural.

==================================================
IMPLEMENTATION STRATEGY
==================================================

Do this incrementally.

DO NOT make hundreds of uncontrolled cosmetic edits in one pass.

1. Audit.
2. Identify shared design primitives.
3. Fix global/shared Android-looking patterns first.
4. Fix remaining page-specific issues.
5. Test.
6. Review visual consistency.
7. Inspect diff for accidental business-logic changes.
8. Build.
9. Run existing tests.
10. Test at iPhone viewport sizes.
11. Only then commit/push.

If changing a shared component risks breaking multiple screens, make the safer scoped change.

==================================================
VISUAL STANDARD
==================================================

At completion, ask:

“If someone opened Lulou on an iPhone without knowing how it was built, would anything immediately make them think Android app, Material Design, generic React website, or cheap PWA?”

If YES, identify and safely polish it.

Then ask:

“Does this still unmistakably look like Lulou?”

That answer must also be YES.

Premium iOS does NOT mean copying Apple.

It means Lulou should feel like a high-quality dating product intentionally built for iPhone.
