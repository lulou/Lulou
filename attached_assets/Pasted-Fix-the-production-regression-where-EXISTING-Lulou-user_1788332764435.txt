The centralized onboarding resolver currently treats missing or legacy values such as:

- `connection_dna_profiles.completed_at`
- `user_settings.onboarding_tutorial_completed`
- `profiles.onboarding_complete`

as proof that an established user must redo onboarding.

That is wrong for users created before these fields/gates existed.

Do not simply set the resolver to fail open globally.

Instead, implement a SAFE LEGACY BACKFILL / COMPATIBILITY RULE.
