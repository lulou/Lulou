This is not an active-session mismatch. The Railway request never returned any HTTP response.

The service worker fetch handler is intercepting the cross-origin Railway API request and calling event.respondWith(fetch(request)). When that fetch rejects, the service worker produces:

FetchEvent.respondWith received an error: TypeError: Load failed

Fix the service worker so it does not intercept any API or non-same-origin request.

REQUIRED SERVICE WORKER FIX

At the very start of the fetch handler:

self.addEventListener("fetch", (event) => {
 const request = event.request;
 const url = new URL(request.url);

 // Never intercept cross-origin requests
 if (url.origin !== self.location.origin) {
   return;
 }

 // Never intercept API requests
 if (url.pathname.startsWith("/api/")) {
   return;
 }

 // Only handle safe same-origin GET navigation/static assets below
 if (request.method !== "GET") {
   return;
 }

 // existing cache logic...
});

Important:

- Do not call event.respondWith() at all for Railway requests.
- Do not intercept:
 https://lulou-production.up.railway.app/*
- Do not cache API responses.
- Do not cache 401, 403, 500 or network failures.
- Do not intercept POST, PUT, PATCH or DELETE.
- Only cache same-origin static GET assets and optionally same-origin navigations.

Also inspect all existing fetch handlers and make sure there is only one active fetch listener.
